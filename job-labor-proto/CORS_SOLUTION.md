# Решение проблемы CORS при локальной разработке

При работе с веб-версией приложения на локальном сервере (localhost) браузер блокирует CORS запросы к удаленному API `https://api.workmatch.dev`.

## Решение 0: Использование мок-сервера (Рекомендуется для разработки)

Если реальный API недоступен или вы хотите работать без зависимости от внешнего сервера, используйте встроенный мок-сервер:

### Запуск мок-сервера:

```bash
npm run mock-api
```

Мок-сервер запустится на порту 3001 и будет эмулировать все эндпоинты API:
- `/api/auth` - авторизация и регистрация
- `/api/verify` - подтверждение email/телефона
- `/api/profile` - профиль пользователя
- `/api/jobs` - вакансии
- `/api/chats` - чаты
- `/api/shifts` - смены
- `/api/reviews` - отзывы
- `/api/workers` - работники

### Настройка:

1. В файле `.env` установите:
```env
EXPO_PUBLIC_API_URL=http://localhost:3001/api
```

2. Перезапустите Expo сервер:
```bash
npm start
```

**⚠️ Внимание:** Мок-сервер использует тестовые данные. Все ответы предопределены и не сохраняются между перезапусками.

## Решение 1: Использование расширения браузера (Рекомендуется для быстрого старта)

Самое простое решение для локальной разработки - использовать расширение браузера для обхода CORS:

### Chrome/Edge:
1. Установите расширение [CORS Unblock](https://chrome.google.com/webstore/detail/cors-unblock/lfhmikememgdcahcdlaciloancbhjino) или [Allow CORS](https://chrome.google.com/webstore/detail/allow-cors-access-control/lhobafahddgcelffkeicbaginigeejlf)
2. Включите расширение
3. Перезагрузите страницу приложения

### Firefox:
1. Установите расширение [CORS Everywhere](https://addons.mozilla.org/en-US/firefox/addon/cors-everywhere/)
2. Включите расширение
3. Перезагрузите страницу приложения

**⚠️ Внимание:** Используйте расширения только для локальной разработки. Никогда не используйте их для работы с реальными данными.

## Решение 2: Использование прокси-сервера (для реального API)

Используйте готовый прокси-сервер из файла `proxy-server.js`:

1. Установите зависимости:
```bash
npm install --save-dev express http-proxy-middleware
```

2. Запустите прокси-сервер:
```bash
npm run proxy
```
или
```bash
node proxy-server.js
```

3. В файле `.env` установите:
```env
EXPO_PUBLIC_API_URL=http://localhost:3001/api
```

4. Перезапустите Expo сервер:
```bash
npm start
```

Прокси-сервер будет работать на порту 3001 и перенаправлять все запросы к `/api/*` на `https://api.workmatch.dev/*`

### Вариант B: Использование готового прокси-сервера

Используйте готовые инструменты:
- [CORS Anywhere](https://github.com/Rob--W/cors-anywhere) (для тестирования)
- [Local CORS Proxy](https://www.npmjs.com/package/local-cors-proxy)

## Решение 3: Настройка CORS на сервере (Требует доступа к серверу)

Если у вас есть доступ к серверу API, настройте CORS заголовки на сервере:

```
Access-Control-Allow-Origin: http://localhost:19006
Access-Control-Allow-Methods: GET, POST, PUT, DELETE, OPTIONS
Access-Control-Allow-Headers: Content-Type, Authorization
```

## Рекомендация

**Для разработки без реального API:** Используйте **Решение 0** (мок-сервер). Это самое удобное решение, так как не требует внешних зависимостей и работает сразу.

**Для работы с реальным API:**
- Для быстрого старта используйте **Решение 1** (расширение браузера)
- Для более стабильного решения используйте **Решение 2** (прокси-сервер)

## Примечание

Проблема CORS возникает только при работе в веб-браузере. При работе на мобильных устройствах (iOS/Android) через Expo Go эта проблема не возникает, так как запросы идут напрямую с устройства, а не через браузер.
